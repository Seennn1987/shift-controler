## 3. UI/UX 自己評価（講師画面）

既存評価シートの「講師体験 3/5」を、今回のコード精査で更新した見立て。

### 3.1 7視点（講師画面に限定）

| 視点 | 点数 | 良い点 | 弱い点 |
|---|:---:|---|---|
| 日常操作 | **2** | ×→○→△の説明あり。下書き→一括送信で誤送信を防ぐ | **2タブ往復**、承認が生徒行単位、月がズレる |
| 情報設計 | **2** | 依頼は赤点線で目立つ | **自分の空き（×○△）と授業が別画面**。確定後が「消えた」ように見える |
| 見た目 | **3** | トークン統一済 | 拒否ボタンが強すぎ。確定行の状態が弱い |
| 学習コスト | **3** | タブは2つのみ | 「カレンダーで選ぶ→教室長に送る」の2段階が初見で分かりにくい |
| 講師体験 | **2** | 変更リクエストの説明は明確 | **コマ単位の現場感とUIが不一致**（1コマ2人を別々に断れる） |
| 安心感 | **3** | 送信前確認あり | 「断る」が強く、断ったあとの関係性が不安 |
| コマ組み適合 | **2** | 90分コマ・定員2人の前提は裏側にある | **UIは生徒行ベース**で、塾の「コマ」単位とズレ |

**講師画面平均: 2.4 / 5**（既存評価 3/5 より厳しめ。統合・コマ単位・消失バグを重く見る）

### 3.2 追加で見つけた UX 課題（指摘外）

| # | 内容 | 影響 |
|---|---|---|
| F | バナー「あとN**コマ**」は実際は**チケット（≈生徒）数** | 1コマ2人で「2コマ」と表示され混乱 |
| G | `myCalYear` と `curYear` が独立 | シフト提出月と授業確認月がズレる |

## 4. 根本原因分析

### 4.1 「断る」が強い（A）

- **原因:** 日常会話で「断る」は人間関係を連想させやすい。danger 色ボタンが拒否感を増幅。
- **データ:** Firestore 内部は `rejected` のままでよい。**講師に見える文言だけ**変更対象。

### 4.2 生徒単位承認（B）

- **原因:** `assignmentApprovals` が生徒1人1チケット。`calendar.js` が行ごとに `setDraftForTicket(ticket, …)`。
- **現場:** 定員2人のコマでは「片方だけ受ける」は運用上あり得ない。
- **例外:** 2教科90分は既に1チケットにまとめる処理あり（`dual-subject.js`）。**同コマ別生徒**だけ未対応。

### 4.3 承認後に消える（C）— **P0 バグ**

主因は次の3つが重なる。

```
┌─────────────────────────────────────────────────────────┐
│ 教室長が確定 → teacherAssignments 同期                    │
│   expandAssignmentForTeacherCalendar()                  │
│     └─ 提出済み teacherSchedules の日付に slot がある日だけ展開 │
│        → シフト未提出月・該当 slot が × の日は **行ゼロ**   │
└─────────────────────────────────────────────────────────┘
```

| 要因 | 説明 |
|---|---|
| **C-1 シフトゲート** | 確定授業も `submitted` シフト上の日だけ表示（`students-persistence.js` L437–444） |
| **C-2 見た目** | `.pending` の赤点線が消えると、確定行が背景に溶ける |
| **C-3 空表示** | 行が0件の日は「確定授業なし」のみ。×○△も出ない |

HANDOFF §8-1 とも整合：**教室長側では見えても、講師側ではシフト未提出月は見えない**。

### 4.4 出勤可否が見えない（D）

- **原因:** `renderMyCalendar()` が `S.myAssignmentEntries` のみ参照。`S.scheduleDoc`（`teacherSchedules`）を読んでいない。
- **結果:** 「いつ働けるか」と「いつ授業があるか」が頭の中で結合できない。

### 4.5 タブ分離（E）

| 項目 | マイカレンダー | シフト提出 |
|---|---|---|
| 画面 | 日付リスト＋生徒行 | 日×コマ表＋×○△ |
| 月 | `S.myCalYear` | `S.curYear` |
| 操作 | 承認／断る／キャンセル依頼 | ×○△／提出／変更リクエスト |

**同じ「自分の1か月」なのに、道具が2つに割れている。**

## 5. 改善方針（AI選定）

### 5.1 文言（A）— 案比較

| 案 | ボタン | メリット | デメリット | 評価 |
|---|---|---|---|:---:|
| W1 | **受けられない** | 事実ベースで柔らかい | やや長い | **採用** |
| W2 | 見送る | 短い | 理由が曖昧 | 次点 |
| W3 | お断りする | 丁寧 | まだ「断り」が残る | 却下 |
| W4 | 対応できません | 最も柔らかい | ボタン2行になりうる | 却下 |

**採用案 W1**

- ボタン: `受けられない`（選択後: `受けられない（選択済）`）
- バナー: `受けられない2件`
- 確認: `…を受けられないと返信します`
- スタイル: danger 赤 → **ghost または muted 枠**（`.mycal-decline-btn`）

### 5.2 コマ単位承認（B）

**UI:** 1日の中を **コマ（4講〜7講）カード** で表示。カード内に生徒を縦並び。**カード末尾に操作1組**。

```
8月22日（金）
┌─ 4講 14:50〜 ─────────────────────┐
│ ○ 出勤可                          │
│ ・テスト 太郎（小5） 国語           │
│ ・テスト 花子（小4） 算数           │
│ [ 受ける ]  [ 受けられない ]        │  ← 2人まとめて
└───────────────────────────────────┘
```

**データ・処理:**

| 層 | 変更 |
|---|---|
| 講師UI | 下書きキーを `slot:{date}|{slotId}` に。1操作で同コマの全 `ticketId` を draft に記録 |
| 送信 | `submitResponseDrafts()` が同コマの全チケットを同じ status で更新 |
| 教室長 | `promotePendingAssignment` / reject も **同コマ同時処理**（既存 dual 2教科と同型） |
| バナー | 未返事数は **コマ数** でカウント（F も解消） |

**ルール:** 同コマに pending が1件でもあればカード全体が「要返事」。片方だけ承認は **不可**（UI上ボタン1組のみ）。

### 5.3 承認後も消えない（C）— **P0**

**採用案 C-A（表示の脱・シフトゲート）**

| 項目 | 変更 |
|---|---|
| 確定授業 | 曜日パターンなら **その月の同曜日すべて** に表示（シフト提出の有無に依存しない） |
| 単発 | `oneTimeDate` どおり1日 |
| シフト | ×○△ は **別レイヤー** で重ねる（空き情報）。表示の条件にはしない |
| 見た目 | 確定コマに **薄い確定バッジ** または左ボーダー（緑系）を常時付与 |

**却下案 C-B:** シフト未提出なら非表示のまま → 消える問題が残る。

**関連ファイル:** `src/admin/students-persistence.js` `expandAssignmentForTeacherCalendar`、必要なら `syncTeacherAssignments` のテスト。

### 5.4 統合画面（D + E）

**新名称:** タブ1つ **「マイスケジュール」**（「マイカレンダー」「シフト提出」を廃止）

**レイアウト（案 U1 — 採用）:** 既存シフト表をベースに拡張

| コマセル | 未提出月 | 提出済み月 |
|---|---|---|
| 空き | ×○△ クリックで編集 | ×○△ → 変更下書き |
| 授業依頼 | 生徒名＋**コマ単位** 受ける／受けられない | 同左 |
| 確定授業 | 生徒名＋確定表示 | 同左＋キャンセル依頼 |

- **月ナビ:** 1つ（`S.scheduleYear` / `S.scheduleMonth` に統一）
- **下部:** 未提出→「この内容で提出する」／提出済→「変更をリクエストする」
- **上部バナー:** 依頼返事・送信待ち（現行と同型）

**却下案 U2:** 日リストのまま ×○△ を足す → コマの横並び比較が弱い。

**却下案 U3:** カレンダー月マス型 → 講師は「何曜日何コマ」より **日付×コマ表** に慣れている（現行シフトタブ実績）。

### 5.5 プレビュー方針

本番 `src/teacher/*` 変更前に、必ずプレビューを作成する（[`ui-reuse-first.mdc`](../.cursor/rules/ui-reuse-first.mdc)）。

```
参照する既存画面: teacher.html + shift-ui.js の grid / calendar.js の行
流用: .grid, .cell-btn, .mycal-lesson-row, .pending-banner-*
新規: .schedule-slot-card（コマ単位カード）— 理由: 統合レイアウト用
プレビュー: docs/teacher-schedule-unified-preview.html（新規）
```
