## 1. 背景・発覚事項

個別指導塾の現場では、**小学生** の来塾パターンは次のとおり。

| パターン | 時間 | 教科 | 位置づけ |
|---|---|---|---|
| **A. 通常（メイン）** | 1コマ **90分** | **1教科** | 大多数。現行どおり |
| **B. 例外** | 同じ90分 | **45分×2**（例：国語＋算数） | 一部の生徒のみ |

中学・高校は **常に1コマ＝1教科**（変更なし）。

> **UI方針:** 登録・マッチング画面は **A（1教科）を主導線** とし、B（2教科）は **折りたたみまたは副セクション** で選べるようにする。2教科を前面に出さない。

現行ピタコマは B に対応しておらず、同じ slot に2教科を置けない。A はすでに動いているが、B 追加時に A の操作感を損なわないことも要件とする。

## 2. 現状の前提（コード上の事実）

| 前提 | 根拠 |
|---|---|
| 1 course ＝ 1 subject | `student.courses[].subject` |
| 1 slot に1教科のみ登録可 | `assignSlotSubject` が他 course から同 slot を除去 |
| マッチングは **1教科** で講師を絞る | `t.subjects.some(ts => ts.level === level && ts.subject === subject)` |
| 割当1件 ＝ 1 subject | `assignments[]` / `pendingAssignments[]` |
| 定員・教室・講師給は **slot 単位** | `countTeacherSlot`, `countRoomSlot`, `perLessonRate` |
| 担当生徒ペアは **course（教科）単位** | `preferredPairs[]` |
| 収入は **assignment 1件 × 学年単価** | `tuitionRates[level]`（双教科ペアは **1コマ分として1回だけ** 計上 — §8 確定） |

**関連ファイル（主要）**

- 定数・slot: `src/shared/constants.js`
- 生徒 slot 登録: `src/admin/student-course-calendar.js`
- マッチング: `src/admin/matching.js`, `teacher-schedule-tab.js`, `matching-config.js`
- 候補 UI: `src/admin/match-candidates-html.js`, `match-candidate-ui.js`
- カレンダー: `src/admin/calendar.js`, `day-detail-panel.js`
- 欠席・振替・収支: `src/admin/absences.js`, `finance-ui.js`
- 講師承認: `src/teacher/approvals.js`, `calendar.js`
- 永続化: `src/admin/students-persistence.js`

## 3. 多角的な影響分析

### 3.1 教室長（登録・日常操作）

| 影響 | 内容 | 深刻度 |
|---|---|:---:|
| 生徒登録 UI | **1教科（90分）が主**。2教科は副セクション（折りたたみ） | 高 |
| 用語・理解 | 大多数は1教科のまま。2教科は「例外」と明示 | 中 |
| マッチング画面 | 候補講師は **両教科対応必須**。片方だけ得意の表示が必要 | 高 |
| カレンダー表示 | 「国+算」等、**複合表示**がないと1教科しか見えない | 高 |
| 担当生徒 | 国語用・算数用で2件登録か、ペア単位か方針が必要 | 中 |

### 3.2 講師（シフト・承認・マイカレンダー）

| 影響 | 内容 | 深刻度 |
|---|---|:---:|
| シフト提出 | 90分 slot 1枠のまま（変更不要の可能性大） | 低 |
| 承認チケット | 現状 `subject` 1つ。2教科を1依頼にまとめるか2件にするか | 高 |
| マイカレンダー | 表示が1行か2行か。講師から見れば **1コマで2教科** | 中 |
| キャンセル依頼 | v1 は **コマ全体** のみ（片方教科だけの休み・振替は不可） | 低 |

### 3.3 マッチング・自動組み

| 影響 | 内容 | 深刻度 |
|---|---|:---:|
| 候補絞り込み | **両方の教科を教えられる講師のみ**（必須要件） | 高 |
| 候補順位 | 片方だけ得意・両方得意のバッジ／優先度 | 中 |
| 自動組み | 双教科 slot は候補数が少なくなり **未充足が増えやすい** | 高 |
| 代替日程提案 | 2教科同時に空いている slot を探す必要 | 中 |
| 確定操作 | 1クリックで **2 assignment を連動** させる必要 | 高 |

### 3.4 定員・教室・シフト

| 影響 | 内容 | 深刻度 |
|---|---|:---:|
| 教室定員 | 1生徒・1 slot・90分 → **1カウント** が自然 | 低 |
| 講師定員 | 1講師が同 slot で2教科連続 → **1カウント** が自然 | 低 |
| シフト整合 | 講師が slot に出ていれば OK（現行ロジック流用可） | 低 |

### 3.5 収支・請求イメージ

| 影響 | 内容 | 深刻度 |
|---|---|:---:|
| 売上 | **1コマ分**（90分・2教科でも `tuitionRates['小学']` × **1**） | 中 |
| 講師給 | **1コマ分**（`perLessonRate` × **1**。slot 単位は現行どおり） | 低 |
| 収支画面 | 内部は assignment 2件だが、**表示・集計は dualGroupId 単位で1行** にまとめる必要 | 中 |

**実装メモ:** `computeDayFinance` 等で、同一 `dualGroupId` の2件は売上・講師給とも **重複計上しない**。

### 3.6 欠席・振替・代講

| 影響 | 内容 | 深刻度 |
|---|---|:---:|
| 欠席登録 | **コマ全体のみ**（2教科まとめて欠席） | 中 |
| 振替 | **2教科セットで移動**（別日・別 slot へペアごと振替） | 中 |
| 代講 | 両方教えられる代講講師が必要。ペアごと差し替え | 中 |

### 3.7 データ・移行

| 影響 | 内容 | 深刻度 |
|---|---|:---:|
| 既存データ | 中学以上・小学1教科は **そのまま** 動く必要 | 高 |
| Firestore | students / assignments / assignmentApprovals の schema 拡張 | 中 |
| 後方互換 | 旧データに `dualSubject` なし → 1教科として扱う | 高 |

## 4. 設計方針（3案比較）

| 案 | 概要 | メリット | デメリット | 評価 |
|---|---|---|---|:---:|
| **A. 同 slot に2 course 連動** | 小学のみ同 `{day,slot}` を2 course に登録可。割当・確定は2件を **ペア ID で連動** | 既存 course 構造を活かせる。教科色・担当生徒を教科別に維持 | 登録・確定・欠席で「ペア同期」ロジックが必要 | **◎ 推奨** |
| B. composite course | `{ subjects: ['国語','算数'], ... }` 1 course 1 assignment | 割当キーが1件でシンプル | subject 前提の全画面改修が大きい | △ |
| C. slot 分割（4a/4b） | 45分単位の slot id を新設 | 時間モデルが正確 | SLOTS・シフト・UI 全体の大改修 | × |

### 推奨：案A（小学限定・2 course 連動）

**データ拡張（案）**

```javascript
// desiredSlot（小学・双教科のみ）
{ day: '月', slot: 4, dualGroupId: 'dual-xxx' }  // 同じ dualGroupId を2 course が共有

// assignment（確定時は2件、連動）
{
  ...既存フィールド,
  dualGroupId: 'dual-xxx',   // ペアを特定
  dualRole: 'first' | 'second' // 表示順（任意）
}
```

**マッチング条件（必須）**

```javascript
teacherCanTeachBoth(teacher, level, subjectA, subjectB)
  = teacher.subjects が subjectA と subjectB の両方を level で満たす
```

## 9. 受け入れ条件（まとめ）

1. **小学生** は **1教科/90分（メイン）** を従来どおり登録できる
2. **小学生** は必要な場合のみ **2教科/90分** を登録できる
3. **中学・高校は現行どおり** 1 slot 1教科（回帰なし）
4. 双教科 slot のマッチング候補は **両方教えられる講師のみ**
5. 確定操作1回で **2教科が同じ講師・同 slot に紐づく**
6. カレンダー・マッチング画面で **2教科が分かる表示**（1教科表示は現行どおり）
7. 既存の単教科データは **変更なしで動作**
8. 双教科コマの売上・講師給は **1コマ分**（2件に分かれていても重複計上しない）
9. 欠席・振替は **2教科セット** で連動（コマ全体欠席のみ）

## 10. リスク・副作用

| リスク | 対策 |
|---|---|
| 候補講師が激減し未充足増 | バッジで「両方対応○人」を登録時に表示。代替日程強化 |
| ペア片方だけ確定されるバグ | `confirmAssignment` で transaction 的に2件まとめて作成 |
| 用語混乱（コマ数 vs 教科数） | 通常は1教科と明示。2教科は「必要な場合のみ」 |
| 欠席・振替の現場差 | v1 は **コマ全体・セット振替** に固定。教科別は将来対応 |
| 収支の二重計上 | `dualGroupId` で集計時に1コマにまとめる（A9） |
