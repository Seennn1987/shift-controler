# 依頼：ピタコマの全データを読める「読み取り専用API」を追加してほしい

## 背景・目的
このリポジトリは、個別指導塾向けのコマ管理アプリ「ピタコマ」です。
- Firebase Hosting：https://shift-controller-4ecaf.web.app/
- Firebaseプロジェクト：`shift-controller-4ecaf`

外部のAIアシスタント（Claude）が、**ピタコマに保存されているすべての情報**（授業・コマ割り、講師、シフト、生徒、給与・交通費、コスト率、キャンペーン、設定など）を読み取れるようにしたいです。そのための **読み取り専用のHTTP API** を追加してください。

**重要な制約（設計に必ず反映してください）**
- 呼び出し側が使えるのは **HTTPのGETだけ** です。**カスタムヘッダー（Authorizationなど）は送れません**。そのため、認証は **URLのクエリパラメータ `key`** で行います。
- 呼び出し側はレスポンスを要約して読みます。そのため、**なるべくフラットで読みやすい構造** にしてください。
- **読み取り専用** にしてください。書き込み・更新・削除の処理は一切含めないでください。
- 既存アプリの動作、Firestoreセキュリティルール、データには **変更を加えない** でください。

## 実装仕様

### 基本構成
- **Cloud Functions for Firebase（第2世代、HTTPS関数）** で実装する
- リージョン：`asia-northeast1`
- Admin SDK を使い、**読み取りのみ** 行う
- タイムゾーンは **Asia/Tokyo** に統一する（「今日」はJST基準で判定）

### 認証・セキュリティ
- クエリパラメータ `key` を必須にする
- キーは **Secret Manager** に保存する（`defineSecret('PITAKOMA_API_KEY')`）
- キーの比較は `crypto.timingSafeEqual` で行う
- キーが違う・付いていない場合は、`401` と `{"error":"unauthorized"}` を返す
- **キーはログに出力しない**
- アクセスログとして、日時・エンドポイント・件数を記録する（キーは記録しない）
- 短時間に大量のアクセスがあった場合に備えて、簡易的な回数制限（レートリミット）を入れる
- Secretを更新するだけでキーを差し替えられる構成にする

### エンドポイント
1つの関数 `readApi` の中で、パスによって処理を振り分けてください。

#### A. 汎用エンドポイント（全データへのアクセス用）
| パス | 内容 | パラメータ |
|---|---|---|
| `/collections` | 全コレクションの一覧と件数。サブコレクションも含める | なし |
| `/collection/{name}` | 指定コレクションの全ドキュメント | `limit`（デフォルト100・最大500）、`cursor`（ページング）、`where`（例：`date==2026-09-28`）、`orderBy` |
| `/doc/{path}` | 指定ドキュメント1件。サブコレクション名の一覧も返す | `path` は `teachers/abc123` のような形式 |
| `/export` | 全コレクションを一括で返す（バックアップ・全体把握用） | `collections`（カンマ区切りで絞り込み可） |

- Timestampは `2026-09-28T17:30:00+09:00` 形式、参照型はパス文字列に変換する
- 各ドキュメントに `_id` と `_path` を付ける
- ページングがある場合は `nextCursor` を返す

#### B. 用途別エンドポイント（毎日使う、整形済みのデータ）
| パス | 内容 | パラメータ |
|---|---|---|
| `/lessons` | 指定日の授業一覧 | `date=YYYY-MM-DD`（省略時は今日）、`teacher=principal` で塾長担当だけに絞る |
| `/shifts` | 講師シフト | `from`, `to`（省略時は今日から7日間） |
| `/students` | 生徒一覧（全項目） | なし |
| `/teachers` | 講師一覧（全項目。給与条件も含む） | なし |
| `/payroll` | 給与集計（コマ単価×確定授業数＋交通費） | `month=YYYY-MM` |
| `/cost` | 売上・講師コスト・コスト率 | `month=YYYY-MM` |
| `/summary` | 指定日のサマリー（下記） | `date` |

#### レスポンスの共通形式
```json
{
  "generatedAt": "2026-09-28T08:00:00+09:00",
  "count": 12,
  "items": [ ... ],
  "nextCursor": null
}
```

#### `/lessons` の `items` の例（フラット構造）
```json
{
  "period": 3,
  "startTime": "17:30",
  "endTime": "18:50",
  "studentName": "山田 太郎",
  "grade": "中3",
  "subject": "数学",
  "teacherName": "佐藤 花子",
  "isPrincipal": false,
  "status": "確定"
}
```
- 並び順：`period` の昇順、同じ時限の中では `teacherName` の順
- `isPrincipal`：担当講師が塾長なら `true`

#### `/summary` の内容
- その日の総コマ数と、出勤する講師の一覧
- **塾長担当の授業一覧**（`period`, `startTime`, `studentName`, `subject`）
- 時限ごとの授業数
- 未確定・振替などの注意が必要な授業

### 塾長の判別
- 調査結果に合わせて実装する
- データ上で判別できない場合は、**環境変数、またはFirestoreの設定ドキュメントに塾長の講師IDを設定する方式** にする
- ハードコードはしない

### エラー処理など
- 日付の形式が不正なとき、または存在しないコレクションが指定されたときは、`400` または `404` とエラーメッセージを返す
- GET以外のメソッドには `405` を返す
- レスポンスに `Cache-Control: no-store` を付ける
- `/export` のような大量読み取りでFirestoreの課金が増えすぎないよう、件数に上限を設ける
