# ピタコマ UI/UX 評価計画 v1.0

**作成日:** 2026-08-21  
**ステータス:** Phase 4 完了（評価レポート確定）  
**目的:** 開発を一度止め、ピタコマの画面・操作体験を競合と比較し、強み・弱み・改善優先度を可視化する  
**スコープ:** 教室長画面（`index.html`）＋講師専用画面（`teacher.html`）の UI/UX。配色詳細は [`配色調査・提案_v1.0.md`](配色調査・提案_v1.0.md) と連携する  

**評価の進め方:** 本計画書に沿って調査 → 比較表記入 → 多角的評価 → 改善ロードマップ作成（実装は別フェーズ）

## 2. 評価の背景

### 2-1. なぜ今、立ち止まるか

- カレンダー・絞り込み・マッチングロジックなど、**中核機能の実装が一段落**した
- 機能を足し続ける前に、「使いやすさ」と「競合との差」を言語化しないと、改善の方向がぶれる
- オーナー（非エンジニア）が日常使う画面のため、**操作のしやすさ・迷いの少なさ**を最優先で測る

### 2-2. ピタコマの位置づけ（評価前提）

| 項目 | 内容 |
|---|---|
| 対象 | **個別指導塾**のコマ組み・シフト・マッチング |
| 主ユーザー | 教室長（メイン）、講師（シフト提出・確認） |
| 競合との差別化 | 「コマを誰に・いつ・どの講師で組むか」に特化。請求・保護者アプリ一体型ではない |
| 参考 | 配色方針は別ドキュメント。本評価では**操作・情報設計・機能の届き方**を中心にする |

### 2-3. 評価対象画面（タブ一覧）

| タブ | 主な体験 |
|---|---|
| カレンダー | 月/週表示、絞り込み、欠席・振替、コマ組みパネル |
| 生徒登録 | 登録、希望コマ、一覧絞り込み |
| 講師登録 | 登録、基本スケジュール、一覧絞り込み |
| シフト管理 | 月次提出、変更リクエスト、確認状況 |
| 分析 | 収支・コスト率 |
| 設定 | 優先順位、休校、季節講習 |
| 講師専用 | シフト提出、担当授業確認 |

## 3. 競合の選定

### 3-1. 選定基準

1. **個別指導・習い事**の運営者が実際に検討するサービスであること  
2. **スケジュール・コマ組み**に関係する機能説明が公開されていること  
3. 比較対象が「全部入り型」と「コマ特化型」の両方含むこと  

### 3-2. 比較対象（5社）

| # | サービス | 選定理由 |
|---|---|---|
| A | **コエテコマネージャー byGMO** | 習い事向けオールインワンの代表。集客・決済・保護者連携が強い |
| B | **wagaco** | コマ組み・予約カレンダーを前面に出す国内競合 |
| C | **Comiru（コミル）** | 塾向けSaaSのシェアが大きく、UIの業界標準になりやすい |
| D | **RESERVA school** | カレンダー中心の予約UI。TimeTree/Googleカレンダーに近い操作感 |
| E | **スクの助** | 小規模塾向け。シンプルさ・価格帯の比較軸 |

※ 比較表の記号は**評価実施時に公式サイト・デモ・口コミで再確認**し、出典を脚注に残す。

## 5. UI/UX 多角的評価（7視点）

各視点を **5段階（1:劣る 〜 5:優れる）** で採点。競合平均との差分も記録する。

### 5-1. 評価視点一覧

| # | 視点 | 見る内容 | 主な確認画面 |
|---|---|---|---|
| 1 | **日常操作の効率** | よく使う操作までのクリック数・迷い | カレンダー、コマ組み |
| 2 | **情報の見つけやすさ** | 一覧、絞り込み、状態（未確定・欠席）の一目性 | カレンダー、マッチング |
| 3 | **見た目・統一感** | 色、余白、ボタン、2行崩れ、古さ | 全タブ |
| 4 | **初回・学習コスト** | 初めて触った人が説明なしで使えるか | 全タブ、用語 |
| 5 | **講師側体験** | シフト提出の分かりやすさ・ストレス | teacher.html |
| 6 | **エラー・不安の少なさ** | 取り消し、解除、確認、元に戻せるか | 絞り込み、確定解除 |
| 7 | **「個別指導コマ組み」適合度** | 競合の汎用予約UIより、現場向きか | マッチング、週間空き |

### 5-3. シナリオ別タスク評価（操作テスト）

## 7. 初期仮説（評価で検証する）

### 7-1. 優れている可能性が高い領域

| 領域 | 根拠 |
|---|---|
| **マッチングの透明性** | 候補順位・バッジ（全コマ対応、指定講師等）が画面に出る |
| **週間の空き・負荷の見える化** | 生徒別/講師別/空き状況の週軸は汎用予約SaaSに少ない |
| **コマ組み特化** | 定員・ブース・優先ペア・希望コマ対応数など、個別指導向けロジック |
| **分析（コスト率）** | 請求一体型競合とは別軸の「組み方の経営判断」 |

### 7-2. 劣っている可能性が高い領域

| 領域 | 根拠 |
|---|---|
| **保護者・決済導線** | 意図的にスコープ外。競合の主戦場 |
| **モバイル** | PC向けレイアウト中心 |
| **初見のやさしさ** | タブ数・用語（コマ、マッチング、優先ペア等） |
| **ビジュアル統一** | 配色・密度・一部レガシーUI残存（配色計画と連動） |
| **オンボーディング** | 初回ガイド・空状態の説明が薄い |

### 7-3. 戦略上の問い（Phase 4 で回答）

1. **追いかけるべき競合機能**はどこまでか？（請求・LINEは本当に必要か）  
2. **差別化を深める**べきはマッチング・カレンダーか？  
3. UI改善の **短期（1〜2週間）** と **中期（1〜2ヶ月）** の切り分けは？
