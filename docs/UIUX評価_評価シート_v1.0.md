## 2. 視点別詳細メモ

### 2-1. 日常操作の効率（3点）

**よく使う操作フロー（現状）**

| 操作 | ステップ概算 | 評価 |
|---|---|---|
| 未確定を1件確定 | カレンダー→日付→候補→確定（3〜4クリック） | ○ |
| 生徒で絞り込み | 絞り込み→選択（2クリック）＋解除（1クリック） | ○ 改善済 |
| 一括仮組み | コマを組む→メニュー→実行（3クリック） | ○ |
| 生徒新規登録 | タブ切替→長フォーム | △ フォームが長い |

**ボトルネック:** 「生徒登録」「講師登録」タブと「カレンダーで組む」が頭の中で別タスクに感じられる。

### 2-2. 情報の見つけやすさ（4点）

- 未充足は `cal-status-bar` に常時1行表示 → 良い
- マッチング候補にランク番号＋バッジ → 良い
- 週間表示の軸切替（生徒/講師/空き）→ 競合に少ない強み
- 課題: カレンダーセル内情報密度が高く、初見は読み取りにくい

### 2-3. 見た目・統一感（3点）

- `variables.css` で MF 系青に更新済みだが、`admin.css` 約1300行で歴史的スタイルが混在
- 講師 `teacher.html` L46: `debugPanel` が本番UIに残存 → **信頼感を損なう**
- 絞り込み2行問題は修正済（2026-08-21）

### 2-4. 初回・学習コスト（2点）

- 6タブ: カレンダー / 生徒 / 講師 / シフト / 分析 / 設定
- ヘッダー副題「曜日・時間割・担当教科の一覧化ツール」→ コマ組みツールとはズレ
- help-tip 多数は資産だが、**一覧性がなく**初見では「?を全部読む」必要がある

### 2-5. 講師側体験（3点）

- 2タブ（マイカレンダー / シフト提出）でシンプル
- 提出済み月の変更→リクエストの説明は `teacher.html` L74 に明記 → 良い
- デバッグパネル・BUILD表記は開発痕跡

### 2-6. 安心感（4点）

- 絞り込み: 「すべて表示」＋「×解除」（2026-08-21 実装）→ 大きく改善
- 確定解除ボタン、一括自動解除あり
- フォールバックで黙って続行する箇所はルールブック上禁止（要継続監視）

### 2-7. 個別指導コマ組み適合度（5点）

- 希望コマ数と希望曜日の整合チェック
- マッチング優先度7項目（カスタム可）
- 週間空き・教科タグ ON/OFF
- 分析タブのコスト率 → 組み方と経営が連動
